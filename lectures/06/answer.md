- やったこと：
  MCPサーバー側（`app/mcp_server.py`）に `server.tool()(tools.get_lecture_summary)` の1行を追記し、既存の `search_glossary` に加えて `get_lecture_summary` ツールを公開した。エージェント側（`app/mcp_agent.py` や `app/mcp_servers.json`）には一切変更を加えず、`--list-tools` でのツール一覧表示、`--trace` 付きでの質問応答（「第2回では何を学びますか？」）、および `uv run pytest -q` による自動テストを実行して動作を確認した。
- 結果：
  - `--list-tools` にて、モデルに見えているツール数が7個から8個に増え、`glossary_get_lecture_summary` が正しく認識された。
  - `--trace "第2回では何を学びますか？"` の実行では、AIが自律的に `glossary_get_lecture_summary({'lecture': 2})` を呼び出し、第2回（ファインチューニングとLoRA）の講義要点を取得して正確に回答できた。

  - エージェント側のコードを一切書き換えなくても、サーバー側にツールを追加して起動するだけで新しいツールが使えるようになった。これは、AIエージェントが起動するたびにサーバーへ「今どんな道具（ツール）が使えるか？」と毎回リストを取りに行く仕組みになっているためだと理解できた。
  - AIはツールの中身（Pythonのコード）を直接読んでいるわけではなく、ツールに書かれた「日本語の説明文」と「引数（整数を入れること）」だけを見て判断している。「『第3回では何を学ぶ？』のように、回の内容や関係を聞かれたときに使う」という説明文があったおかげで、AIが質問の意図を汲み取って「このツールに 2 を入れて使えばいい」と正しく選択できていることがわかった。

- やったこと：
  `app/tools.py` に、指定された回の用語集からランダムに1問分のクイズ素材を返す `make_quiz(lecture: int)` 関数を新しく実装し、`app/mcp_server.py` に `server.tool()(tools.make_quiz)` を追記して公開した。存在しない回が指定された場合はエラーで落とすのではなく、現在データが存在する回の一覧（`[1, 2, 3, 4, 6]`）を含めた案内メッセージを文字列で返すように設計した。そのうえで、`--list-tools` および `--trace` 付きで正常な回（「第2回のクイズを作って」）と範囲外の回（「第99回のクイズを作って」）の動作を確認した。
- 結果：
  - `--list-tools` にて、`glossary_make_quiz` が新しく認識され、ツール一覧が9個に増えた。
  - `--trace "第2回のクイズを作って"` では、`glossary_make_quiz({'lecture': 2})` が呼ばれ、用語の定義文のみを出題して回答を促すクイズが正しく生成された。
  - `--trace "第99回のクイズを作って"` では、`glossary_make_quiz({'lecture': 99})` から「第99回の用語データが存在しないためクイズを作成できません。現在クイズを作成できる回は [1, 2, 3, 4, 6] です。」という戻り値がAIに渡り、AIがそれを踏まえて「第1回、第2回、第3回、第4回、第6回のいずれかのクイズを作成しますか？」とユーザーに代替案を提示できた。
- 気づき・疑問：
  - ツールの引数が範囲外だった場合、プログラムをエラーで異常終了させるのではなく、「なぜ実行できないのか」と「代わりに指定できる有効な値（今回は1, 2, 3, 4, 6回）」を分かりやすい日本語で返してあげると、AIがその情報を読み取ってユーザーに親切な聞き返しをしてくれることがわかった。
  - ツールの戻り値（JSON）の中に、データだけでなく「答えはすぐに見せず、ユーザーが回答できるようにすること」といった振る舞いの指示を含めることで、AIの出力形式をコントロールできる点も興味深かった。

- やったこと：
  VS Code の公式ドキュメントで MCP サーバーの設定方法（ファイルの置き場所、JSON の記述形式、適用スコープなど）を調べ、演習で使用した `app/mcp_servers.json` と比較した。
- 結果（演習の `app/mcp_servers.json` との比較）：
  1. 設定を書く場所：
     - 演習：`app/mcp_servers.json` に直接記述する。
     - VS Code：現行の Copilot harness（ポータブル形式）では個人全体用が `~/.copilot/mcp-config.json`、プロジェクト共有用がワークスペースルートの `.mcp.json` に配置される（互換用の従来形式では `.vscode/mcp.json` やユーザープロファイルの `mcp.json` も存在するが非推奨扱い）。また、JSON を直接編集するだけでなく、コマンドパレットの `MCP: Add Server` や `Chat: Open Customizations` から対話的に追加できる。
  2. コマンドで起動する書き方（stdio）：
     - 演習：トップレベルキー `"mcpServers"` の下にサーバー名を置き、`"command"` と `"args"` を指定する。
     - VS Code：ポータブル形式（`.mcp.json` / `~/.copilot/mcp-config.json`）では演習と全く同じ `"mcpServers"` + `"command"` + `"args"` の形式で書ける。一方、従来の `.vscode/mcp.json` 形式ではトップレベルキーが `"servers"` になり、`"type": "stdio"` を明示する違いがある。
  3. URL で接続する書き方（HTTP）：
     - 演習：`"aws": {"url": "https://knowledge-mcp.global.api.aws"}` のように `"url"` だけを記述する。
     - VS Code：`"url"` に加えて `"type": "http"` のように通信方式（type）を明示して記述する。
  4. 有効になる範囲：
     - 演習：`app/mcp_agent` を動かしたこのプロジェクト内でのみ有効。
     - VS Code：設定ファイルの置き場所によって、「そのプロジェクト（ワークスペース）だけ」で有効にするか、「すべてのプロジェクト（グローバル）」で有効にするかを使い分けられる。
- 気づき・疑問：
  - VS Code の現行のポータブル形式（`.mcp.json`）は、トップレベルキーが `"mcpServers"` で演習の `app/mcp_servers.json` とほぼ同じ書き方になっており、異なるツールやエージェント間でも設定を流用しやすいように標準化が進んでいることがわかった。
  - 演習用のシンプルなエージェントと異なり、VS Code のような実際の開発エディタでは、チーム共有用と個人用のスコープ分離や、Workspace Trust（信頼されていないフォルダでの勝手なコマンド実行防止）、OAuth 認証・シークレット管理といったセキュリティや運用面の仕組みが細かく組み込まれている点が印象的だった。
